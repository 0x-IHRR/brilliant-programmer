## 运行

需要 Docker、uv、Bun。命令在仓库根目录执行；仅创建专用本地数据库，不访问其他容器。

```sh
python3 scripts/init_local.py

bun install --frozen-lockfile
bun run --cwd frontend build
uv run --directory backend uvicorn app.main:app --host 127.0.0.1 --port 18080 --no-proxy-headers
```

## 账号契约与边界

- `POST /api/v1/users/signup`：邮箱、用户密码、邀请码。邮箱统一小写；不可由请求设置管理员、等级或验证状态。初始为小白程序员、邮箱未验证。
- `POST /api/v1/login/access-token` 与 `GET /api/v1/users/me`：Argon2 密码校验、JWT 登录（1 小时）及数据库会话归属/过期检查；`POST /api/v1/login/logout` 删除当前会话，随后页面清除 sessionStorage，旧令牌即时不能发起新请求，其他设备仍可用。在途请求不保证撤销。升级前不含会话 ID 的旧 JWT 需重新登录。密码重置成功在同一事务撤销该账号所有会话，详见 T03。
- `GET /api/v1/training/access` 使用共享 `get_training_user`，未验证邮箱返回 403。后续所有训练路由必须复用该依赖；此接口只检查准入，不声称训练业务存在。
- 管理员独占 `POST/GET /api/v1/invitations` 和 `POST /api/v1/invitations/{id}/revoke`；列表每页 100 个，可刷新/翻页查询真实状态，不暴露注册人资料。邀请码是 256 位随机持有凭证，产品仅向管理员返回；不自动过期、不绑定收件人。
- 注册及作废锁定同一邀请行；账号 INSERT 与 `used` 在同一 PostgreSQL 事务提交。重复邮箱或插入失败回滚，不耗码；并发只能注册或作废一方生效。已用码不可恢复。重复作废幂等。浏览器未收到响应时先登录已有账号或由管理员刷新状态，不因超时恢复邀请码。
- 服务端未挂载模板的公开无邀请注册、私有测试用户创建、管理员用户列表/修改/删除、改邮箱、长期密码邮件或第三方登录接口；找回仅开放下述原已验证邮箱流程。
- 登录/注册按连接客户端地址与路径分别限制每分钟 60 次，计数由 PostgreSQL 原子更新，过期记录清理。只存 HMAC 地址摘要；本地服务不信任代理头。生产使用前需设计可信代理及运营限速，不将本机规则称为完整生产防护。
- 本地邮件仅交付受控 Mailpit，无真实邮件、短信、分析上报或模型调用。邀请数据库和 `.env` 需按秘密保护；操作者技术访问不等同产品管理员权限。

## 邮箱验证与恢复（T02）

注册事务先建立账号并耗用邀请，再通过标准库 SMTP 发送验证邮件；响应 201 的 `verification_sent` 区分交付成功/失败，SMTP 失败不会撤销已建立账号或恢复邀请码。用户随后登录自己的训练首页，未验证时只允许查本人信息、重发、确认验证和退出；管理员原有邀请权限不因验证而扩展。所有训练入口必须使用 `get_training_user`，目前 `/training/access` 仅验证这条共享边界。

- 链接是 256 位随机一次性凭证，数据库仅存 SHA-256 摘要、账号及原邮箱；默认 30 分钟（`VERIFICATION_EXPIRE_MINUTES`）。用户必须登录对应邮箱账号后点击确认，收到邮件/打开页面本身不改变状态。URL fragment 由页面读取后清除，不放到 HTTP 查询/访问日志；刷新丢失待确认链接时重新打开邮件即可。
- 成功重发使旧链接失效，每账号成功发送后 60 秒可重发；同账号发信与验证在 PostgreSQL 行锁下串行。验证成功删除凭证；重复/并发确认最多成功一次。发信失败保留此前有效链接；超时交付不明或邮件交付后数据库提交失败时，新链接可能无效，用户可重新发送。不保证 SMTP 与数据库分布式原子提交。
- 发送最多等待 5 秒连接/每次 socket 操作；未实现后台邮件队列或自动重试。注册响应丢失可先登录查看真实状态，不能凭页面报错认定注册失败。退出失败保留本机凭据供重试，不显示成功。
- `POST /users/me/verification-email` 返回 200（已交给收件服务/已经验证）、429（稍后重发）、503（发送失败，可重试）；`POST /users/me/verify-email` 接收 `{token}`，成功 200，格式错误 422，无效/过期/重放/邮箱不匹配 400。以上路径带 `/api/v1` 前缀，均要求有效会话（401）；训练未验证 403。发信/验证沿用每客户端每路径每分钟 60 次限制。
- `SMTP_HOST/SMTP_PORT/SMTP_FROM` 默认本机测试端；支持可配置 `SMTP_STARTTLS`、`SMTP_USER/SMTP_PASSWORD`，认证必须使用 TLS，证书由系统信任链校验。本轮仅执行 Mailpit 明文回环测试，未测试真实 SMTP、认证、外部投递或投递到达率；真实服务配置需另获授权。Mailpit 端口只能本机访问，邮件包含可验证凭证，勿公开收件服务。

并行本机测试可在 `.env` 指定 `DB_PORT`、对应 `DATABASE_URL`、`SMTP_PORT`、`MAILPIT_HTTP_PORT`、`FRONTEND_HOST`、`PLAYWRIGHT_BASE_URL`、`MAILPIT_URL`；运行 API 时使用对应端口。API 测试用 `MAILPIT_URL` 环境变量（默认 `http://127.0.0.1:18025`），例如 `MAILPIT_URL=http://127.0.0.1:18035 uv run --directory backend pytest tests -q`。浏览器配置自动读取 `.env`。测试无真实邮件；初始/重发失败用受控异常注入，正常路径从真实 SMTP 收件端读取邮件。

验证覆盖：API 的未登录/跨账号/伪造/过期/重放/并发确认、SMTP 失败恢复、退出旧令牌失效/其他设备有效；Playwright 的注册→本地收件→登录→错误链接→确认→准入→退出→旧凭据拒绝与退出网络失败恢复。无部署、无训练内容与模型调用验收。过期会话记录当前保留，数据库留存清理属于后续运维配置。

## 个人模型配置（T04 #5）

邮箱验证后显示独立个人配置区域；未验证账号沿用首页的有限操作边界，配置 API 返回 403。每账号至多一套已保存配置，未配置返回 `null`，无默认 Key。首次及每次保存由页面明确确认运营者能解密、指定模型服务接收必要学习材料；服务地址改变会清除确认，必须重填 Key。管理员没有他人配置或 Key 回读入口。

- `GET /api/v1/model-config` 仅返回本人的 `version/service_url/model_id/has_key`，绝不返回 Key、密文或加密材料。所有成功配置响应 `Cache-Control: no-store`。
- `PUT /api/v1/model-config` 接收 `{service_url, model_id, api_key, expected_version, disclosure_accepted}`。首次 `expected_version: null`，修改传上次读到的 UUID；不一致 409，保留当前数据，不覆盖新版本。`api_key: null` 只可在地址未变时保留当前 Key；每次保存生成新 UUID（包括只改模型 ID），旧引用失效。
- `DELETE /api/v1/model-config?expected_version=UUID` 删除当前整套配置及在线密文；已不存在时幂等 204，版本变更时 409。UI 先确认再执行。不删除学习数据。重新保存使用新 UUID，旧引用不能复活。
- 保存仅校验本地输入并持久化；HTTPS（默认 443 或显式合法端口 1–65535）、无账号、查询、fragment，拒绝明显本地地址、内网 IP 及异常域名。**不解析 DNS、不向供应商发请求**，因此保存不是连通性或出站安全验收。实际出站的 DNS/重定向/代理/目标绑定由 T05 #6 每次连接验证；教学质量也未验证。
- 参数错误 422 不回显输入（含畸形 JSON）；401 要重新登录，403 未验证，409 要刷新重编，503 加密材料不可用／解密失败。前端提交后总是清空 Key，只保留普通输入；失败不会显示保存成功，不自动重试，不写 localStorage/sessionStorage。刷新配置会明确丢弃未保存编辑。

加密使用 `cryptography` 的 AES-256-GCM，随机 96 位 nonce，认证绑定账号 ID、配置 UUID、地址、模型 ID 和加密材料版本，防止搬运密文到别的账号或目的地。数据库只保存密文及非秘密版本标识；独立的 `MODEL_ENCRYPTION_KEYS` 由进程环境或仓库忽略的权限 0600 `.env` 提供，格式 `{"v1":"<32随机字节的标准Base64>"}`，`MODEL_ACTIVE_KEY_VERSION` 默认 `v1`。`scripts/init_local.py` 生成本机独立材料；已有 `.env` 不覆盖。没有有效材料时账号功能仍可用，但保存/使用凭据失败关闭，绝不退回 JWT SECRET_KEY 或明文存储。环境文件与数据库备份必须分开保管，服务器运营者技术上仍能解密；不要把真实 Key 用于本地测试。

旧本机环境需在保留原 `.env` 的前提下，由操作者新增独立随机材料。轮换先保留旧版本，再增加新材料及切换 `MODEL_ACTIVE_KEY_VERSION`，重启 API/worker；配置下一次保存（同地址可留空 Key）会以新版本重新加密。确认数据库不再引用旧版本，并满足最长 30 天备份窗口后，才可退役旧材料。丢失某版本材料无法还原该版 Key，用户可重新填写替换或删除。已用伪材料验证新旧版本共存、重加密、旧材料移除后的读取，以及材料缺失/密文篡改失败关闭。

后续调用模块统一使用 `app.model_config.service.credential_for_call(session, user_id, version)`：`user_id` 必须来自服务端认证或已核验归属的持久任务，不能信任请求自报身份；持久任务只存账号和配置版本。用独立 Session/事务包住上下文和一次真实请求，禁止在上下文外缓存/使用明文；里面再做实际出站目的地安全校验。上下文与保存/删除锁定同一账号行，旧版本/跨账号引用 409；每次请求均重新验证账号可用、邮箱验证及当前版本。当前简化为持锁覆盖一次调用，调用方必须限制在 120 秒内；保存/删除可能等待这次请求结束，成功后旧版本不能新派发。尚无实际模型调用或运行任务；#15 再实现停止/尝试取消及迟到结果标识，当前不声称已经实现取消。

本地验证使用 bp-issue-5 隔离 PostgreSQL 和伪 Key：25 项专项 API 检查包含 fresh Python 进程重读、替换/删除/重建撤销、跨用户、格式错误不回显、加密材料缺失/轮换/认证篡改及并发单胜、调用锁顺序与已缓存账号被停用后的拒绝；Playwright 检查真实邮箱验证→保存→刷新→替换失败恢复→替换→删除与手机宽度、浏览器存储无 Key。未建立备份或生产部署，不能将本地删行视为备份恢复验收；启用备份恢复前必须实现删除重放，禁止恢复旧 Key 后直接开放调用（后续数据留存/部署票）。


## 密码找回与全设备重登（T03 #4）

登录页和已登录首页均提供「忘记密码」。用户只填写原邮箱；无管理员代改、替换收件人、更换登录邮箱或迁移账号入口。请求中的额外身份/收件字段会被拒绝。仅有效且已验证账号收到邮件，收件人始终取账号数据库中的原邮箱。

- `POST /api/v1/password-reset/request` 接收 `{email}`，邮箱忽略大小写。已验证、未验证、不存在、停用、重发冷却及 SMTP 失败均返回相同 202 和泛化正文；202 **只表示已受理，不确认账号存在或投递成功**。未收到可一分钟后重试；不会自动重试。每客户端每路径每分钟 60 次，超限 429 / `Retry-After: 60`；每账号成功发送后 60 秒内不再发信。同步 SMTP 可能带来耗时差异，未声称抵御计时侧信道或已具生产防滥用能力。
- 链接为 256 位随机一次性凭证，数据库仅保存 SHA-256 摘要及所属账号/原邮箱，默认 30 分钟（`PASSWORD_RESET_EXPIRE_MINUTES`）。成功重发立即替换旧链；失败保留此前链接。SMTP 最多等待 5 秒连接/每次 socket 操作，超时交付不明或交付后数据库提交失败时新链可能无效，重新申请即可。邮件与数据库不具分布式原子提交。
- URL 使用 `#reset=…`；页面读取后移除 fragment，不写入浏览器持久存储，不随页面 HTTP 请求或 Referer 发送。仅打开/申请不修改账号或会话；刷新丢失链接时重新打开邮件。邮件不包含用户密码。提交后清空新密码输入，网络失败保留当前链接供重试；响应丢失时可尝试新密码登录或重新申请，不能据报错断定未重置。
- `POST /api/v1/password-reset/confirm` 接收 `{token,password}`，无须旧会话。12–128 字符的新密码及有效链才可成功；200 明确所有设备需重登，400 表示无效/过期/已用/账号绑定失效，422 表示格式错误（包括畸形 JSON 和额外字段，响应不回显密码/凭证），429 表示请求保护；事务故障为失败响应，不自动重试。所有客户端遇到需登录接口的 401 清除本机令牌并提示重新登录。
- 登录密码校验和会话创建、重置、重发均锁定同一用户行并刷新已有 ORM 状态。重置成功在单一 PostgreSQL 事务更新 Argon2 密码、耗用链接并删除全部旧 `LoginSession`；并行同链最多成功一次，旧密码登录若先拿锁，其刚建立会话也被重置删除；若后拿锁则按新密码拒绝。当前只有一小时访问令牌，没有刷新凭据或自动换新令牌路径。
- 仅撤销此账号会话，不改用户身份/邮箱验证/等级/模型配置；学习业务记录尚未实现，因此本轮不能声称验证未来学习表的保存。已通过认证的在途请求不保证撤销，后台任务停止不由密码重置推导。

## 连接测试与模型 ID（T05 #6）

保存、测试连接、获取模型 ID 是独立操作。后两项只使用编辑中的地址和**重新填写的 Key**，不会读取已保存 Key；列表不要求模型 ID。页面在点击前说明目标、可能收费及重试，Key 提交后清空。列表结果只提供选择，选择才回填，仍需另点保存。修改地址、模型、Key、确认框或刷新/保存/删除使旧结果失效；迟到请求不会覆盖新输入。失败和空列表保留手填。并发操作按钮禁用，输入仍可编辑；不会承诺在途请求取消或退款。

- 基地址按填写路径去尾 `/` 后拼接 `/chat/completions` 或 `/models`，不猜测补 `/v1`，不切换服务。Chat 请求仅含 `model`、固定 user 消息「请仅回复 OK」及 `stream: false`；服务返回有效非空文本即本次连通，不回显回复，也不证明判分质量。不支持工具调用、Responses API 或多模态。兼容子集：JSON `choices[0].message.content` 字符串；也能读取返回的 UTF-8 SSE `data:` JSON、index 0 的 `delta.content`、末尾 `[DONE]`，不将半截流判成功。SSE 在服务端完整验证后返回摘要，不逐字转发至浏览器。列表须为 JSON `data` 数组，每项 `id` 为合法字符串；最多 2000 项、ID 最长 255 字符，不分页猜测或逐模型测试。返回内容按不可信文本处理，拒绝包含本次 Key 的模型 ID。

- `attempts` 保留本次各次尝试序号/分类与供应商 `prompt_tokens/completion_tokens/total_tokens`，缺失或无效数字分别为 `null`（显示未知）；失败时仍保留已完整收到的 JSON 用量或完整 SSE 事件中的合法数值，中断的 JSON／事件不推测。401/403/402 响应头立即结束，不为收集用量等待响应体，不估金额、不把未知补零，也不设置累计 token/任务额度。它是本次响应统计，刷新后不保留，不是账单或后续持久训练任务的汇总。持久任务预算、结果、防重及重启恢复由 T07 #8 实现，不能把这两个短操作当后台训练任务。

### 任务与调用契约

- `POST /api/v1/training/random` 接收 `{disclosure_accepted, expected_config_version, previous_run_id?}`，不接收账号、Key、客户端 messages、目标卡或等级。返回 202；同账号已有进行中任务时返回原任务。`previous_run_id` 须属于本人，仅用于主动换另一个目标。
- `GET /training/tasks` 返回本人最近 20 个任务；`GET /training/tasks/{id}` 查看进度、已交付案例和逐次 token；`POST /training/tasks/{id}/stop` 显式停止。以上均带 `/api/v1` 前缀，复用训练鉴权，响应 `no-store`，跨账号 404，未验证 403，会话失效 401。
- 状态为 queued → running → completed / failed / stopping → stopped。completed **仅表示生成任务结束**，不是完成训练或通过判断。关页不取消，返回只读原任务；停止或失败不会自动新建后续训练。
- 停止先提交 `stop_requested`，原生队列 abort 与异步监测尝试取消在途请求，再获取与真实调用共用的账号锁；成功响应才表示停止已生效。账号锁由独立线程取得/释放，不阻塞异步事件循环。已取得预算但尚未发送 HTTP 的屏障路径也已实测取消，停止成功后不再发送。迟到已校验候选和已收到用量仍保留；取消不能保证供应商停算或退费。
- 配置替换/删除沿用已有账号锁：可等待在途请求结束，成功后旧版本不能新调用。下一次 attempt 重查账号及配置版本，旧任务终止。全关联任务预告及配置变更时主动取消由 #15 接续；本票没有提前开放该扩展。
- 每次外呼前持久计数并建立独立 attempt；单调用最多 3 次、畸形候选最多纠错一次、同一步总计最多 6 次，每次网络调用至多 120 秒。退避 1/2 秒。仅临时连接、临时 DNS、超时、限流和 500/502/503/504 自动重试；认证、余额、地址/TLS/协议错误不重试。已知错误写入后崩溃，恢复也不会把它冒充未知重新派发。
- worker 心跳默认 10 秒；恢复使用库 `get_stalled_jobs` 的 30 秒心跳失活判定，启动时及每分钟检查一次，不按任务运行时长猜测死任务。同一业务 ID 和持久预算继续恢复，已有结果/已停状态短路；SIGKILL 留下的请求用量未知，不能假设没计费。数据库不可用时不能承诺及时报告状态，恢复后应重新读取。

## 自由主题与路线版本（T19）

自由主题入口接受白话。空白保留随机入口；非工程与需要澄清的输入给出说明，允许直接改写。主题分析先生成候选，再由模型读取实际输入、目录和候选内容进行独立核对，通过后才显示目标卡；这不是人工教学质量认证。明确主题给一个目标，宽泛主题给3—5个起步节点和推荐首目标。分析、确认路线及开题是三个动作，分析或逐段展开不会自动创建训练题。

路线保存不可变版本，当前候选与已确认版本指针分开。局部编辑只替换指定节点，重排必须保留全部现有身份，逐段展开只追加下一段，因此超过5个节点后不会被缩回单段。保持原目标文本、重点和能力键的节点保留身份；语义编辑不猜测与旧节点等价。原题、已完成节点、正式作答、草稿、帮助、修为及证据保留。完成标签只依据该节点对应轮次的完整正式作答事实，不以模型候选、题目发布或仅保存原答就标记完成。

分析复用同一 Procrastinate、凭据许可、撤销监测及 JSON/SSE 安全检查。每次真实调用先保存尝试身份，已收到用量尽早落库；未收到仍为未知。停止先存意图，队列取消后经 User 锁确认；旧队列的迟到收尾不能覆盖新重试。模型配置删除后旧路线和题目仍可读，旧配置不能产生新调用。分析阶段不发送旧正式作答、隐藏评分或帮助全文。

## 评分复核与历史回算（T24 #25）

冻结评分后可受理一次复核；`POST /training/tasks/{run_id}/review` 在账号事务内保存原题、原来源、原答及冻结前许可澄清、原评分与原答排序身份，并与队列原子提交。相同 request_id 重放读取同一事实，不同身份再次申请返回 409。解析后的复盘补答不进入复核，原 Evaluation、作答、来源和观察记录不覆盖。`GET` 无需 Key，返回本人已受理状态、复核依据及逐次用量；不返回隐藏帮助或密钥。

复核执行状态与结论分开：网络/配置/存储失败仍是 pending，不能伪称 disputed。模型提出维持、更正或仍争议，程序重新核对原答逐字引用、原材料事实、原规则与结论关系；用户异议或自报信心不作为改判证据。pending/disputed 暂不作为能力成功、失败或连续次数的依据，其他练习可继续。有效复核 grading 在完整历史陌生性及原帮助资格确认之后、每个 Boss 判断的证据检查之前使用，按不可变原答次序与当前全部历史回算，保留期间新增记录；不得用一次总判替代缺域的综合判断证据。已开放单元与等级保留，新的开放只使用当前有效证明。复核及迟到帮助回执均不触发 Boss 晋升或降级；终态确认原晋升缺少有效通过时，按下方 #28 追加待补验事实。

`retry` 需明确确认当前已保存配置，恢复同一复核及累计最多六次预算，每次派发最多三次尝试。已记录的永久错误在同配置恢复时不重新调用；新配置可在剩余预算内主动恢复。每条 attempt 固定自身配置版本、目的地、模型及用量，配置更换不改旧归属。停止先持久化意图并尝试取消；未知/在途请求可能计费，收到的 token 不因后续核对、撤销或存储失败丢失。队列身份保护迟到收尾与旧恢复不会覆盖新派发；存储恢复后可读取并主动继续，不无限重置预算。

原轮修为按 completion-v1.0 仍仅完整完成一次 10 点；更正本身不制造完成。结算累计原奖励与已有补差，只补 `max(0,应得−累计已发)`，不扣已发点数；后续普通结算也读取此累计事实。0022 只新增复核、逐调用和补差表，保留全部旧评分/原答/顺序/奖励；数据库保护受理快照、终态结论与调用归属不可变，有复核事实时拒绝降级丢数据。

专项：`uv run --directory backend pytest tests/test_review_rules.py tests/test_reviews.py tests/test_review_history.py tests/test_review_boss.py tests/test_review_awards.py -q`；运行 API 后 `uv run --directory backend python tests/review_browser.py`。浏览器使用真实 API/数据库/独立 worker/受控 TLS，覆盖受理后失响应与刷新、一次机会、原评分保留、删除 Key 后读取、320px/200%与键盘操作。迁移检查 `tests/review_migration.py` 在专用临时 schema 保留已验证资源，须先有专项合成记录；不触碰其他项目数据。机制测试不验证真实模型的语义判定质量、来源教学适配或大规模历史的响应时间；逐次读取全历史并重新核对的成本沿现有投影边界保留，无缓存捷径、历史截断、自动过期或生产部署。


## Boss 误判后的关联补验（#28）

已生效晋升的评分终态更正后，服务器用该轮冻结原答（含合法中立澄清）、资料、帮助与陌生性资格及逐必考范围重新核对。只有确认原晋升缺少有效通过，才追加关联原 `BossPromotion` 的待补验事实；pending、仍争议、系统失败或历史证据不足不会伪称确认误判。等级、累计修为、已开放单元和原晋升均保留。`0023_boss_revalidation` 对已有终态更正按相同冻结判据回填，不联网、不按当前等级猜旧阶段。

Boss 入口展示每条原晋升及有序复核／解除历史；用户选择一条待补验、确认原阶段标准与当前模型目的地，再主动开始独立新案例。受理保存真实较高的 `launch_level` 和具体要求事件身份，不把用户等级改回旧阶段。补验全部必考有效独立通过只解除这条关联；初评被复核更正为有效独立通过，也只解除该轮冻结绑定的当前要求，不新晋升。失败、帮助、未知交付不解除。多条要求需逐条补足。若一次解除所依据的补验自身又被终态复核确认误判，则追加同原晋升的新要求，保留前次解除历史；旧周期回调和重复请求不能覆盖后来有效解除。

任意待补验期间仍能学习、做普通 Boss。普通 Boss 的发起或结算遇到待补验，会把本轮晋升处置冻结为不晋升；以后清空要求也不会利用旧评分／回执补升，须主动开始新挑战。每轮完整作答仍沿既有一次10点，不因补验另发晋升奖励。所有关联事件、轮次处置采用 User 同事务锁和追加事实，数据库拒绝更新或删除已保存事实；新 API 字段是 `revalidation_of` 与 `expected_revalidation_event_id`，旧发起请求保持兼容。

验证入口：`pytest tests/test_boss_revalidation.py -q`、`python -m tests.boss_revalidation_migration`、`python -m tests.boss_revalidation_browser`，在专用数据库串行运行。浏览器使用真实 API／独立 worker／受控 TLS，覆盖失响应后读取原轮、空白原答、草稿恢复、补验解除与再挂回、删除 Key 后读取、320px／200%及键盘操作。迁移检查保留旧字段全部快照，历史不足保未知，并核追加事实禁止修改和有记录时禁止降版。受控机制检查不认证真实模型的教学语义；全历史比较和多晋升事件读取沿既有路径，未验证任意长期规模，没有生产部署或真实付费模型调用。

## 评分质量证据与准入（#29）

模型连通、结构有效、评分质量和学习效果是不同事实。保存配置和固定连接测试不触发质量评测。没有适用报告时明确显示“评分可靠性未验证”；已有报告但配置 UUID、实际接口、模型、评分规则或来源快照不同，显示版本不匹配。未知仍允许带限制说明的独立训练；精确适用的已知失败阻止新增独立证据与 Boss 晋升，普通练习和复盘可继续。尚未获取来源的开始操作若已有同配置／规则失败，保守拒绝，并告知来源适用性尚不能确认；用户可先普通练习获取新来源，或由受信任操作者导入复测。实际结算按完整来源身份再次检查。

报告入口仅是服务器操作者的本地命令，不是产品管理员权限、用户接口或新评测按钮。操作者先在授权范围内核对真实执行配置、人工标注与逐项输出，再明确提供所审核文件的 SHA-256：

```sh
# backend 目录；只导入本地已有证据，不访问模型或外部链接。
../.venv/bin/python -m app.quality.import_report report.json \
  --sha256 REVIEWED_REPORT_SHA256 --evidence-directory /absolute/path/to/evidence
```

`app/quality/rules.py` 定义版本化报告：账号与配置 UUID、接口、模型、评分规则、素材／标注版本、复测前序报告、84 个案例和至少168个答案样本。每领域三档均有案例，且每例包含可接受和明确错误／证据不足答案；实际样本计算总体一致率95%、每领域90%、安全错误放行0。报告不接收客户端 `passed`。每个引用文件以其 SHA-256 为文件名：真实 Candidate、来源正文、冻结 EvaluationInputs（含原评分许可的一次中立澄清）、标注、实际 GradingCandidate，以及原件绑定的来源核对说明。导入验证字节、现有题目与评分校验器、指定判断项和标签对应；不会用模型信心代替标注。原件与报告持久存入私有数据库，公开接口只返回版本、汇总与摘要，隐藏答案和完整作答不会进入质量页面。

这些检查不判断人工标注或技术语义本身是否正确。操作者的原件审核是信任边界，持有服务器／数据库技术权限不能被描述成产品管理员“任意改分”功能。当前只执行合成协议、事务和受控 TLS 测试；没有运行 #40 的真实模型批量评测或完成人工质量认证，更不宣称学习效果。

导入与实际结算复用 User 事务顺序，复测必须引用当前前序，重复导入不新建结果。原评分和复核分别冻结实际配置下的质量处置，失败轮复测后不由旧回调补发证明或晋升，新主动轮方可继续；已成立的历史质量快照不因后来的报告变更被覆盖。现有复核的争议排除、原序回算、已开放访问、等级与每轮10点规则保持各自事实。报告和处置追加保存；迁移将既有记录固定为“未验证”，不补造真实评测成绩。

容量边界：本地导入单报告最多20MB、单原件20MB、原件合计200MB；这是受信任文件接入的资源边界，不是学习次数上限。质量读取目前解析本账号历史报告以选择确切版本，适合首版小规模报告数量；未验证大规模报告积累吞吐，不新增后台评分或缓存平台。

## 永久删除资料与记录（#31）

“我的记录与资料管理”区分归档与永久删除。永久删除须当前密码重新认证、预览具体关联对象与影响，再明确最终确认；范围变化会要求重新预览。删除本人正文与依赖副本，保留无正文标记、已发修为、等级及已开放权。被删证据不可用，不判成新的能力失败；已见历史缺失会阻止后续陌生性检验，普通练习仍可继续。共享公共附件只在没有有效引用时清除，不能伤及其他账号。边界及进行中的验收见 [永久删除记录](docs/permanent-deletion-validation.md)。


### 注销账号与独立删除重放（#32）

账号注销与删除单份资料分开：重新认证、查看全账号影响并最终明确确认后，先持久化不可撤销意图，登录与旧 JWT、新模型许可立即拒绝；成功响应前排空原调用许可。随后同一后台队列物理清除账号、加密 Key、会话、验证/重置凭据、草稿、学习与成长档案。仅保留无原文的账号 UUID、请求编号、不可逆回执摘要、受理/完成时点及恢复水位；不沿用 #31 保留活跃账号奖励/等级档案的语义。其他账号仍引用的共享质量附件保留。能力回执可以在账号已清除、未登录页面查询，既不恢复旧 JWT，也不允许按任意用户编号注销。

独立 SQLite 日志由 `ACCOUNT_ERASURE_JOURNAL` 指定（默认 `../.private/account-deletions.sqlite3`），权限0600，不能随 PostgreSQL 旧备份一起回滚。新空库显式执行 `initialize-empty`；可信既有在线库首次升级才由运营者明确执行 `adopt-live`。恢复必须保有原独立日志，先迁移再运行 `python -m app.account_erasure.operations replay`；API 与生产 worker 启动也先重放，缺失或不匹配日志、未应用完整连续前缀均拒绝开放，不能把旧库缺少元数据当新安装。原备份之后受理的注销仍按日志重放，原能力回执不依赖备份内存在预览行。

`python -m app.account_erasure.operations audit` 检查受理后24小时内的实际在线清除，保留期工具仅管理其明确登记的本地受控 dump；30天退出时保留独立无原文日志。持续运行、外部备份清单与不可变存储/备份恢复的运营演练由 #33 接续。本票受控数据与时钟验证不代表生产24小时/30天保障已经部署。完整恢复可复跑 `python -m tests.account_erasure_restore`（专属合成 PostgreSQL 容器，CI显式提供容器ID），真实0028 pg_dump/restore、加密Key/会话/草稿与另一账号逐字段比较、生产worker缺日志拒绝/先重放、原能力回执及受控dump到期均有实际断言。
