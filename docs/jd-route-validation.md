# JD 路线实现与验证

JD 原文以稳定分析请求身份保存为不可变 `JDDocument`；同一 Topic 队列执行分析、独立模型核对和每阶段三次／总六次预算。每次调用仍沿已保存配置版本、目的地和撤销门禁，模型核对不代表人工语义质量认证。没有岗位要求或不确定背景时请求补充；多岗位分别展示，用户选择一个岗位后才形成路线。

`JDAnalysis`、`JDRoute` 将原文、所选岗位、精确引用、明示／推断与 Topic 版本绑定。用户修改的是训练卡目标、重点和三档难度，原文要求不被改写为个人偏好。排序保留节点身份，修改节点建立新身份；显式确认后才能开题，前置不足返回真实缺项。已开始题、正式原答、帮助、奖励和旧路线不回滚。

JD 与普通主题共用生成、私人候选核对和全历史独立比较。生成仅发送确认目标、重点、所选要求引用、明示／推断、教学模拟标记与必要公开来源，不默认发送整份 JD 或旧学习档案。完整历史引用协议保留上述 JD 限定和实际 `topic_coverage` 门禁，缺失／拒绝核对不得发布。题目和恢复视图明确标为教学模拟，不声称公司真实架构、故障或面试题。

证据投影使用完整能力／难度／背景键和当前复核解释；同一个短只读数据库快照读取路线、历史和证据。无匹配证据是尚未验证，不表示不会；不能映射的背景为未知。读取失败保留现有界面并明确失败，不能伪造无证据结论。

本票还修复继承的 Topic 结果提交与配置撤销竞态：`User → TopicJob → ModelConfig` 行锁内提交，复用 `current_for_result`。原只读撤销检查在检查完成后仍能先提交撤销；确定性 PostgreSQL 屏障在普通 Topic 与 JD 路径均复现旧实现失败，修后撤销先赢拒绝结果、结果先赢完整保留。
