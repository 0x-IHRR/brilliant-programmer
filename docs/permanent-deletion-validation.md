# 永久删除来源与学习记录（#31）

本记录是实现和软件检查证据，不是生产删除、备份退出或人工教学质量验收。当前尚在完成完整验收；最终全套回归和 CI 将继续补记。

## 行为与实际范围

已验证账号可读取本人记录，将轮次、路线来源或固定项目分析归档，或输入当前密码取得十分钟有效的删除预览。预览不删除；最终必须确认“永久删除所列资料及副本”。重新核对同一账号、目标、密码版本与当前私有副本闭包；中途新增材料或来源版本改变时返回 409，要求重新预览，不静默扩大范围。管理员身份不扩大所有权。

删除在一个事务内追加无正文标记并清空正文。保留原始身份、序号、用量、奖励、等级、开放事实和删除回执，既有原答不能被替换成另一份答案。已删除题面、原答、复盘和来源的旧读取返回 410。删除失败全部回滚，同一回执可查询实际状态并幂等重试。密码变更使未完成预览失效。

| 指定对象或依赖 | 实际清除的私有内容 |
| --- | --- |
| 学习轮次 | selection、来源、Candidate、正式与补充作答、相关性结论、评分冻结输入/来源/结果、复核快照/意见 |
| 帮助与编辑器 | 请求/隐藏生成稿/检查结果、交付正文、TrainingDraft、PracticeDraft、所有冲突/历史草稿正文 |
| 主题/JD 路线 | 各 TopicJob 输入与候选、各版本目标快照、JD 原文/分析/路线；直接关联训练副本 |
| 指定项目分析 | 采集快照/地图/原 URL、引用同分析的复用副本、绑定模块路线、冻结材料来源；不会沿路线家族删除另一个更新版本 |
| 后续独立比较 | 只清引用被删题的完整历史/计划/比较结果；后续轮自己的题目与答案保留，证据不可用 |
| 本人质量报告引用 | 精确来源/题目/原答身份关联的报告清空；共享附件在当前无有效引用时清除 |

项目当前版本若指向所删版本会清空，不偷偷改选旧版。归档只改变列表显示；它不清除正文、证据或奖励，单份“删除当前草稿”也仍使用原有机制。

被删除的已见题保留无正文 exposure 标记。完整历史语义比较不能靠遗漏旧题或 hash 证明陌生，后续独立检验明确退出且不发模型请求；普通练习仍可继续。依赖证明投影为 `evidence_unavailable`，不是新的错误或能力失败，也不能作为新的解锁依据。

## 复用与受限删除边界

沿用 User 顺序锁、现有来源/路线/草稿模型和任务队列。显式字段表只允许固定空值；迁移给原 immutable trigger 增加“有同 owner 删除标记、仅固定字段变为空”的例外，其他不可变条件继续执行。删除标记和完成回执不可改写；旧身份的插入或恢复原文被数据库拒绝，不能把它当通用改分接口。晚到 worker 的预算/发布检查仍生效，删除终态不被普通 finish 改回；已实际收到的用量仍可记录。

共享附件以 SHA 识别字节，不归某一个账号独占。导入与删除按同一排序取得逐 SHA 事务锁，取得锁后查询当前有效引用。另一个账号新导入相同公共字节是合法新操作；已删除报告/原答身份的重放不能重新关联。

多查询读取继续使用原有新 Session、REPEATABLE READ、只读事务。单连接先取得 session advisory shared 锁，再建立 RR 快照；删除持同 owner exclusive 锁，避免等锁前就固定旧快照。finally 释放锁，清理异常 invalidate 物理连接。没有扩连接池或另造读取服务；跟练复用同一个投影快照，不嵌套申请第二个投影连接。

这里保证在线数据库的已盘点正文及旧写入保护。已发送供应商的内容、用户自行下载的文件、离线设备内存和外部公开原件不能由该按钮远程擦除。#30 实际 JSON 导出、#32 注销和 #33 备份恢复运营仍须接入同一删除事实并独立验收，本票不冒称已完成。

## 当前检查证据

在独立 PostgreSQL/受控 TLS/真实独立 worker 上分批通过 18 个本票专项：精确预览、跨 owner 与管理员拒绝、密码改变、CAS、事务失败回滚/重试、归档、三类来源闭包、正式评分/编辑器副本清除、原奖励保留、旧写入拒绝、依赖比较而非递归删除、证据不可用、独立退出/普通练习、在途 worker gate 后零 attempt/零 HTTP、生产 process 重放退出。

并发测试使用真实 PostgreSQL waiter 而非等待固定时长猜测：同 SHA 导入先/删除先均保其他账号有效字节；读取先阻删除、删除先阻读取且最终 GET 410；独立限 4 连接的池能同时承载 4 个只读投影，SQL 错误路径后锁已释放。

初版测试发现并修正固定空对象检查中的 JSONB 包含关系问题，以及旧 ProjectRun/Submission status CHECK 缺少 deleted 终态。空库实际完整迁移至 0028，旧开发 schema 保留，未 stamp。顺序附件测试曾把既有其他测试账号合法保留的公共 source SHA 误当最后引用；改用本次唯一原答附件验证最后引用清除，保留全部跨账号字节断言。

软件静态检查：mypy 123 源文件和 ruff 通过，SDK 按实际 OpenAPI 生成，前端构建通过。完整后端/浏览器/迁移旧数据证据和最终提交 CI 尚待完成。

Ponytail：复用现有模型与队列；只增加删除事实和显式依赖清单。当前闭包遍历本人完整历史，质量报告附件也须实际查找；未测大账号总体延迟，不裁剪影响范围或静默漏删来隐藏成本。新增正文列必须同步字段清单/关系测试；这是有界显式清单的维护成本，不是自动全库字符串擦除。
